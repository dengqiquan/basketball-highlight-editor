# 独立视频合并设计

## 目标与范围

在桌面端“导出集锦”页的“返回审核”旁增加“合并已有视频”入口。用户从本地选择至少两个视频，按界面显示的顺序合并，选择保存位置后得到一个 MP4。此功能独立于当前项目的视频、分析、审核候选、标签、导出设置和导出历史；原文件只读，不会被覆盖。

## 界面

入口打开独立对话框。对话框提供“添加视频”（可多选 MP4、MOV、M4V、AVI、MKV）、已选文件列表、上移/下移、移除和“合并导出”。再次添加会接在列表末尾，重复路径只保留一次。少于两个文件时不能开始。选择保存位置后显示处理状态；完成时展示输出路径及打开所在文件夹的操作，失败时显示原因并允许重试。取消文件选择或保存位置选择不启动合并。

## 处理流程

桌面端通过独立的 Engine 命令提交输入路径顺序及输出路径，再轮询该任务的状态。Engine 不需要 `project_root`，也不写当前项目数据库。开始前验证每个输入是存在、可读的视频，检查输出路径不指向任一输入。输出统一为 MP4；各输入依次转成一致的画面尺寸、帧率、视频编码和 AAC 音轨，无音轨时补静音，再按列表顺序拼接。处理使用临时目录和原子写入，成功后清理临时片段；失败或取消也清理临时产物，保留所有原文件。UI 在任务运行时阻止重复启动，并可取消任务。

## 错误与边界

无法解码、缺失文件、无写入权限、空间不足和编码失败都应反馈可理解的错误。用户选择的输出文件若已存在，沿用系统保存对话框的覆盖确认；若其实际路径与任一输入相同，即使名称省略扩展名或经过符号链接，也拒绝开始。关闭对话框不会让处理卡在一次长请求中；任务可轮询和取消。输出不计入当前项目导出历史。

## 验证

Engine 测试覆盖输入顺序、不同编码或尺寸、无音轨输入、输入输出冲突、失败清理和取消。桌面端测试覆盖入口、添加与排序、少于两个文件禁用、保存位置取消、任务状态和错误反馈。运行相关 Python 与 Flutter 测试，并检查格式和静态分析。
