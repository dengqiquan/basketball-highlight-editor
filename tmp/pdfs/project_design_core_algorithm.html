篮球进球集锦编辑器
详细设计与一级核心算法逻辑

Basketball Highlight Editor · 基于当前仓库实现整理 · 2026-10-31

项目以本地视频为输入，自动找出疑似进球片段，由用户审核、调整范围，并从原视频导出集锦。

导入视频 → 设置篮筐 ROI → 代理粗扫 → 原视频精筛 → 证据判决 → 人工审核 → 导出

3. 一级核心算法：桌面标准分析链

3.1 生成代理并粗扫

Engine 为指定分析范围生成低帧率代理视频，在用户设置的 ROI 内按固定时间采样。检测器识别球与篮筐，输出每个采样点的类别、置信度、边界框和球心。标准模式代理目标框默认 960×720、5 FPS；实际尺寸保持原视频宽高比。模型输入为 640×640，裁切放大倍率受输入尺寸约束。

3.2 估计篮筐并提出粗候选

篮筐检测框的中心和尺寸采用中位数估计；对移动机位，按时间窗口估计局部篮筐。若球先在筐线上方、随后在下方，下降幅度足够，且轨迹与筐线的交点落在筐口允许范围内，就提出疑似穿框候选。粗扫重在召回，不能单独证明进球。

r = (rim_y - y_above) / (y_below - y_above) x_cross = x_above + r × (x_below - x_above) event_time = t_above + r × (t_below - t_above)

3.3 回源精筛与轨迹关联

标准模式围绕每个粗候选的时间点回到原视频，默认在前后各 2.5 秒窗口内以 10 FPS 采样。它重新检测球和篮筐、构建多条球轨迹，并恢复短暂遮挡导致的断轨。局部篮筐位置还会根据窗口内的稳定检测重新校准。

精筛要求球从篮筐上方进入筐口走廊、穿过筐线，在筐下形成连续实测点；仅凭两个点插值穿过筐线，不算完整穿框。中间轨迹明显偏离、横向运动过强或下降速度异常的候选会被过滤。对球短暂遮挡的情形，下降轨迹拟合可提供人工复核证据。

3.4 汇总证据并判决

证据判定用途
完整穿框与筐下持续性确认球真实穿过筐口并继续向下。
篮网区域变化比较篮网上、中、下区域的图像变化和激活顺序；单独记录测量是否有效。
反弹与侧向离开识别近筐回升、从篮筐旁离开的反证据；深处落地反弹不作为撞框反弹。
几何与校准门槛综合球速、横向跨度和篮网信号，决定高精度与自动导出资格。

判决为 made、missed 或 ambiguous：强反证据判 missed；完整穿框、筐下持续性及相应正向证据满足门槛时判 made；不足以确认的保留 ambiguous 供人工审核。made 和 auto_export_eligible 是不同字段。

3.5 篮筐局部复核、去重与入库

Engine 对最终候选在篮筐附近逐帧复核，更新候选证据。相近时间的候选通常按 2 秒窗口归并，综合 verdict、完整穿框、证据来源和分数选代表事件。候选入库包含事件时间、默认片段范围、分数、检测版本和完整证据 JSON。

4. 快速模式与移动端

快速模式：代理目标框为 640×480、3 FPS，跳过原视频精筛，粗扫结果直接进入审核并标记 coarse 来源。它速度更快，但可能漏检，证据强度也低于标准模式。

移动端：Flutter 应用独立运行，通过平台媒体层抽帧，由 Rust/ONNX Runtime 检测与判决。跨端契约统一事件时间、完整穿框、篮网可用性、反弹、侧向离开、verdict 和自动导出资格。两端抽帧与模型执行仍不同，真实视频结果一致性需要回放验收。

5. 人工审核与导出

用户可保留或排除候选、调整片段起止点和标签。导出使用审核后的时间范围，从原视频编码片段；合并模式先处理重叠片段，再拼接，直接拼接失败时回退到重新编码。分析结果服务于审核，最终输出由人工选择状态和片段范围控制。

核心逻辑概括：低成本粗扫找可能事件；原视频精筛验证球的真实运动；结合篮网变化和反证据给出保守判决；不确定事件交由人工审核；按审核结果从原视频导出。
